# 運用手順（アイデア出し → 公開）

関連: [[strategy]] / [[article-guide]]。1回の実行で記事は最大1本。

1. **アイデア出し**: `topics.txt` の先頭から選ぶ。尽きたら WebSearch で「困りごと」を調べて補充（公式ヘルプ、Q&A、季節の事務作業）。同じ切り口の既存記事がないか `content/` を確認。
2. **調べる**: 公式ドキュメントで仕様・画面・料金を確認。URLと確認日をメモ。
3. **動かして確かめる**: 手順は実際に動かす（この端末の Python・PowerShell・Office 等で再現できるものを優先）。動かせなかった手順は「確かめていない」と明記。
4. **書く**: `python new_post.py <slug> "<タイトル>" <公開日>` → [[article-guide]] の型で中編（3,000〜4,500字）。
5. **推敲**: yomiyasu スキルで推敲（最終稿は `_work/`）。
6. **検査**: `python check.py`（エラー0）→ `python build.py`。字数警告は理由なく無視しない。
7. **公開判断**: 確かめた手順だけの記事は `draft: true` を外して公開日を設定。【体験メモ】が要る記事は下書きのまま。
8. **記録**: `topics.txt` から外し、`plan/log.md` に1〜3行。報告は「何をしたか／確認できたこと／未確認のこと」。

## やらないこと
体験の捏造、出典なしの数字、yomiyasu を通さない公開、個人情報の記載、アカウント作成・課金・push（指示があるときだけ）。
