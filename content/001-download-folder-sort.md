ダウンロードフォルダ、気づくと何百個ものファイルが並んでいませんか。

探したいPDFが見つからず、結局もう一度ダウンロードし直す。そんな経験がある人は少なくないと思います。

この記事では、Windows標準のPowerShellだけで、ファイルを種類別のフォルダに仕分ける方法を紹介します。いきなり動かさず、先に「どこへ移すか」を一覧で確認できます。移したあとも、記録を使って元に戻せます。

## 結論：コピペ1回で、画像・PDF・書類・圧縮ファイルに分けられる

やることは、短いスクリプトを貼り付けて実行するだけです。

最初は「予定の表示」だけで、ファイルは1つも動きません。内容を見て問題なければ、設定を1か所変えて、もう一度実行します。

動かすのは、拡張子（ファイル名の最後の「.pdf」のような部分）で決められる4種類だけです。

- 画像（jpg、jpeg、png、gif、webp）
- PDF
- 書類（docx、xlsx、pptx、txt、csv）
- 圧縮（zip、7z）

それ以外のファイルや、ダウンロード途中のファイルには触りません。

## 手順1：PowerShellを開く

スタートメニューで「PowerShell」と入力し、「Windows PowerShell」を開きます。

管理者として実行する必要はありません。普通に開いてください。管理者権限で動かすと、操作を間違えたときの影響が大きくなります。

## 手順2：スクリプトを貼り付ける（まずは予定の表示だけ）

次のコードを、そのまま貼り付けて Enter を押します。

```powershell
$src   = "$env:USERPROFILE\Downloads"   # 整理するフォルダ
$apply = $false                          # $false=予定を見るだけ / $true=実際に移動

$rules = [ordered]@{
  '画像' = '.jpg','.jpeg','.png','.gif','.webp'
  'PDF'  = '.pdf'
  '書類' = '.docx','.xlsx','.pptx','.txt','.csv'
  '圧縮' = '.zip','.7z'
}
$log = Join-Path $src '整理ログ.csv'

$rows = foreach ($f in Get-ChildItem -LiteralPath $src -File) {
  $folder = $rules.Keys | Where-Object { $rules[$_] -contains $f.Extension.ToLower() } | Select-Object -First 1
  if (-not $folder) { continue }
  $destDir = Join-Path $src $folder
  $dest    = Join-Path $destDir $f.Name
  if (Test-Path -LiteralPath $dest) {
    [pscustomobject]@{ 結果='スキップ'; 元=$f.FullName; 先=$dest }; continue
  }
  if ($apply) {
    New-Item -ItemType Directory -Force $destDir | Out-Null
    try {
      Move-Item -LiteralPath $f.FullName -Destination $dest -ErrorAction Stop
      [pscustomobject]@{ 結果='移動'; 元=$f.FullName; 先=$dest }
    } catch {
      [pscustomobject]@{ 結果='失敗'; 元=$f.FullName; 先=$dest }
    }
  } else {
    [pscustomobject]@{ 結果='予定'; 元=$f.FullName; 先=$dest }
  }
}

$rows | Format-Table 結果, @{n='元';e={Split-Path $_.元 -Leaf}}, @{n='先';e={$_.先.Replace($src,'')}} -AutoSize
if ($apply) { $rows | Where-Object 結果 -eq '移動' | Export-Csv $log -Encoding UTF8 -NoTypeInformation }
```

実行すると、次のような表が出ます。「予定」と書かれた行が、これから移す予定のファイルです。

```
結果     元          先
--       -           -
予定     b.jpg       \画像\b.jpg
予定     report.pdf  \PDF\report.pdf
スキップ memo.docx   \書類\memo.docx
```

この段階では、ファイルは1つも動いていません。何度実行しても安全です。

## 手順3：表の見方と、見るべきポイント

見てほしいのは、次の3点です。

- 「元」の名前に、移したくないファイルが入っていないか
- 「先」のフォルダ名が思った場所になっているか
- 「スキップ」が出ていないか

「スキップ」は、移動先に同じ名前のファイルがすでにある、という意味です。上書きで消えてしまうのを防ぐため、このスクリプトはその1つを動かさずに残します。残ったファイルはあとで自分で見て判断してください。

移したくないファイルがあるときは、そのファイルを別のフォルダに避けてから、手順2をもう一度実行します。

## 手順4：問題なければ、実際に移動する

表に納得できたら、貼り付けたコードの2行目を書き換えます。

`$apply = $false` を `$apply = $true` にして、もう一度実行してください。

今度はファイルが実際に移動します。画像は「画像」フォルダへ、PDFは「PDF」フォルダへ、という具合です。フォルダがなければ自動で作られます。

移動した内容はダウンロードフォルダの中の「整理ログ.csv」に残ります。これが、あとで元に戻すときの手がかりです。

## うまくいかないとき

よくあるつまずきを2つ挙げます。

**1. 赤い文字のエラーが出て、何も動かない**

コードの一部だけが貼り付けられたり、引用符が全角に変わったりしていることがあります。いったん閉じて、コードを最初から貼り直してください。

また、ダウンロードフォルダの場所を変えている人は、1行目の `$src` を実際の場所に書き換える必要があります。

**2. 表に「失敗」と出て、一部が動かない**

そのファイルを、別のアプリが開いている状態であることが多いです。アプリを閉じてから、もう一度実行します。

失敗したファイルだけが元の場所に残り、ほかのファイルは通常どおり移動します。失敗した行は整理ログに入らないので、元に戻すときにも影響しません。

## 間違えたとき：整理ログから元に戻す

「やっぱり戻したい」ときは、次の2行を実行します。

```powershell
$log = "$env:USERPROFILE\Downloads\整理ログ.csv"
Import-Csv $log -Encoding UTF8 | ForEach-Object { Move-Item -LiteralPath $_.先 -Destination $_.元 }
```

整理ログには、「どのファイルを、どこからどこへ移したか」が1行ずつ書かれています。それを逆向きにたどって、全部を元の場所へ戻します。

ただし、移したあとにファイル名を変えたり、別の場所へ動かしたりしていると、そのファイルは戻せません。戻したいときは、整理した直後にやるのが確実です。

また、整理ログは実行するたびに上書きされます。2回目の整理をしたあとは、1回目の記録は残りません。

## 向いている人・向いていない人

向いているのは、次のような人です。

- ダウンロードフォルダがいつもごちゃごちゃしている
- ファイルの種類で探すことが多い
- 手作業の仕分けが面倒で続かなかった

向いていないのは、次のような人です。

- 「請求書」「領収書」のように、中身で仕分けたい人（拡張子では分けられません）
- 仕事用の共有フォルダを整理したい人（他の人のファイルを動かすと困るため）
- コードの貼り付けに、どうしても抵抗がある人（その場合は、エクスプローラーの並べ替え機能で拡張子順にして、手で選んで動かす方法があります）

会社のパソコンでは、PowerShellの利用が禁止されていることがあります。ルールを確認してから使ってください。

## 動かして確かめたこと

この記事の手順はWindows 11 の Windows PowerShell 5.1 で動かして確かめました（2026年11月23日）。

使ったのは、自分の実際のダウンロードフォルダではなく作ったばかりのテスト用フォルダです。拡張子の違うダミーのファイルを9個置き、次の動きを見ました。

- 予定の表示のあいだは、ファイルが1つも動かないこと
- 同じ名前のファイルがあるときは、スキップして残ること
- 拡張子が対象外のファイルは、そのまま残ること
- 整理ログから、移動したファイルを元の場所に戻せること
- 別のアプリで開いているファイルは「失敗」と表示され、残りは移動すること

確かめていないこともあります。

- PowerShell 7 や、Mac・Linux での動作
- 何千個ものファイルがあるフォルダでの速さ
- OneDrive で同期しているフォルダでの動作

特にOneDriveの同期中のフォルダは、移動の途中で同期が走ると、思わぬ動きをするかもしれません。最初は少数のファイルで試すことをおすすめします。
